# DLC Diagram Viewer: run and upload

> **STOP - before reading on: invoke the skill `domainlifecycles` now if it is not
> loaded yet** (mode check, marker types the uploaded model depends on).

Targets DLC 3.5.x and the Diagram Viewer from `esentri/diagram-viewer`
(`llms.txt`, `README.md`, `USER_GUIDE.md` there). Diagram files generated by the
build (nomnoml/SVG) -> `dlc-diagrammer`; call-graph answers as text ->
`dlc-impact-analysis`.

## Prerequisites (check first)
- Docker with Docker Compose (`docker compose version`).
- Free ports **8090** (viewer UI/API) and **8000** (Kroki). PostgreSQL needs no
  host port (see compose template).
- The project uses DLC marker types (Mode B or C). Classes outside
  `domainModelPackages` or without marker types are missing in the viewer.
- DLC build plugin 3.4.0+ for the static analysis upload (3.5.0 recommended).

## 1. Start the viewer
1. If the viewer repository is checked out, use its
   `docker/run/docker-compose.yaml`. Otherwise write the template from
   `references/docker-compose.yaml` to `.dlc/diagram-viewer/docker-compose.yaml`
   in the project and **ask before committing it** (suggest adding `.dlc/` to
   `.gitignore`).
2. Start: `docker compose -f <compose file> up -d`
3. Wait until healthy - never assume it is up:
   ```bash
   for i in $(seq 1 60); do
     curl -fs http://localhost:8090/actuator/health | grep -q '"UP"' && break; sleep 2
   done
   ```
4. Tell the user the URL: <http://localhost:8090>.

Stop / reset: `docker compose -f <file> down` (keeps data only if a volume is
configured - the template has none, so projects and users are gone afterwards).

## 2. Account and API key (manual - the agent cannot do this)
The upload authenticates with the user's API key (`X-API-KEY`). Ask the user to:
1. open <http://localhost:8090>, **Create Account** (no e-mail validation, no
   password reset - note the password), **Log in**,
2. user menu (circle top right) -> **Copy API-Key**,
3. provide it as environment variable `DLC_VIEWER_API_KEY` in their shell.

**Never write the API key into a build file, `AGENTS.md`, a commit or a log.**
Don't echo it back.

## 3. Configure the upload
Static analysis is on by default (`runStaticAnalysis = true`); it enables the
viewer's flow filters and the Read Models / Commands analyses.

Gradle (task `domainModelUpload`):
```groovy
plugins { id 'io.domainlifecycles.dlc-gradle-plugin' version '3.5.0' }

dlcGradlePlugin {
    domainModelUpload {
        diagramViewerBaseUrl = "http://localhost:8090"
        apiKey.set(providers.environmentVariable("DLC_VIEWER_API_KEY"))
        projectName = "shop"
        domainModelPackages = ["com.example.shop"]
        runStaticAnalysis = true
        // include infrastructure packages, otherwise flows stop at repository /
        // outbound-service interfaces (implementations are not found)
        staticAnalysisPackages = ["com.example.shop"]
        streamUpload = false        // true for large domains (avoids OutOfMemoryError)
    }
}
```
(Gradle plugin resolution: see `dlc-diagrammer` - no plugin marker on the portal.)

Maven (goal **`uploadDomainModel`** - the upstream example's
`<goal>domainModelUpload</goal>` is wrong):
```xml
<plugin>
  <groupId>io.domainlifecycles</groupId>
  <artifactId>dlc-maven-plugin</artifactId>
  <version>3.5.0</version>
  <executions><execution>
    <id>upload</id>
    <goals><goal>uploadDomainModel</goal></goals>
    <configuration>
      <diagramViewerBaseUrl>http://localhost:8090</diagramViewerBaseUrl>
      <apiKey>${env.DLC_VIEWER_API_KEY}</apiKey>
      <projectName>shop</projectName>
      <domainModelPackages><domainModelPackage>com.example.shop</domainModelPackage></domainModelPackages>
      <runStaticAnalysis>true</runStaticAnalysis>
      <staticAnalysisPackages><staticAnalysisPackage>com.example.shop</staticAnalysisPackage></staticAnalysisPackages>
    </configuration>
  </execution></executions>
</plugin>
```
Further options: `staticAnalysisCacheSize` (default 5000), `uploadRequestTimeoutMinutes`
(default 5), `nonDomainExcludedPackages` / `nonDomainExcludedSupertypePackages`
(generated code), `staticAnalysisExpandNonDomainDispatch` (default false, noisy).
Use this execution only on demand (no `<phase>` binding), so a normal build does not
need a running viewer.

## 4. Upload and verify
- Gradle: `./gradlew domainModelUpload` (compiles first).
- Maven: `mvn compile dlc:uploadDomainModel@upload`.
- The first upload of a `projectName` creates the project for the API key's owner;
  later uploads update it only if that user is assigned to the project (creator or
  "Share Project") - otherwise rejected.
- Ask the user to refresh the browser: the project appears on the left. Diagrams of
  existing projects regenerate automatically after an upload (every 30 s check).
- Flow filters / "Analyze Bounded Contexts" with Read Models and Commands are
  available only if the static analysis was uploaded.

## Troubleshooting
| Symptom | Cause / fix |
|---|---|
| Health check never `UP` | `docker compose logs diagram-viewer-app`; port 8090 busy; database not healthy yet |
| Upload: connection refused / timeout (10 s connect) | viewer not running or wrong `diagramViewerBaseUrl` |
| Upload rejected | wrong / missing API key, or the user is not assigned to an existing project of that name |
| Build runs out of memory during upload | `streamUpload = true`; lower `staticAnalysisCacheSize` |
| Upload times out on large domains | raise `uploadRequestTimeoutMinutes` |
| Flow filter shows only a hint | uploaded with `runStaticAnalysis = false` - upload again with analysis |
| Flows end at interfaces | add infrastructure packages to `staticAnalysisPackages` |
| Classes missing | outside `domainModelPackages` or no DLC marker type |
| Large diagrams fail to render | raise `KROKI_COMMAND_TIMEOUT` (compose) and `KROKI_REQUEST_TIMEOUT_SECONDS`; restrict the diagram with filters |
| Viewer slow / OOM with many large projects | `DIAGRAM_VIEWER_JAVA_OPTS="-Xmx4g ..."` |
